# Projects 活动轨道与信号档案详情卡设计

## 背景

Projects 页的活动轨道目前存在两个直接影响理解的问题：

1. 桌面端曲线下沉到视口底部，活动文字又沿曲线向下排布，导致轨道在页面中段被文字遮挡，并在视口边缘显得断裂。
2. 节点只显示当天第一条活动的标题，且被强制压成一行。组件没有 hover、键盘聚焦或触摸展开的详情状态，因此用户无法读到活动摘要，也无法理解同一天的其他活动。

本次调整只处理活动轨道与详情交互，不改变 Projects 项目卡、活动数据结构、发布接口或分页逻辑。

## 设计目标

- 轨道在桌面端从地球安全区外连续延伸到卫星方向，中段始终清晰可见。
- 默认状态即可识别日期、活动数量和首条活动主题。
- hover、键盘聚焦和触摸操作都能打开完整、清楚的活动详情。
- 同一天有多条活动时，详情卡必须列出全部活动，不能只展示第一条。
- 视觉继续使用 Projects 页现有的深空终端语言，不引入独立的卡片风格。

## 方案选择

采用已确认的 A「信号档案」方案。

- 保留细直角边框、冷青信息色和琥珀信号色。
- 使用近黑半透明底与轻微背景模糊，保证星空上方的文字对比度。
- 标题使用现有无衬线字体，元数据使用等宽字体。
- 不采用 B「遥测终端」的重型侧栏，避免详情卡抢过项目卡与轨道的主次。
- 不采用 C「星图札记」的衬线与金色装饰，避免 Projects 页向 Writing 页的手稿风格偏移。

## 轨道与默认节点

桌面端继续使用一条 SVG 贝塞尔曲线，但将曲线整体抬离视口底部，并为最低点保留稳定的底部安全距离。轨道层位于星空与地球之上、活动节点之下；节点圆点准确落在曲线上。

活动文字不再压在线条上。每个节点的默认信息区放在线条上方，与圆点之间保留清晰间距，内容包括：

- `MM.DD` 日期；
- `N 项活动`；
- 首条活动的项目名和完整短标题，最多显示两行。

曲线不依赖文字背景遮罩制造断点。中段即使没有节点也必须连续可见。地球左侧安全裁切继续保留，但裁切终点只覆盖地球本体，不得影响第一个可见节点之后的轨道。

移动端继续使用垂直时间线，不显示桌面曲线。

## 信号档案详情卡

详情卡采用直角档案面板：

- 背景为高不透明度的近黑色，并加入轻微 `backdrop-filter`；
- 边框使用低亮度冷青色，顶部增加一段短琥珀信号线；
- 阴影只用于从星空中分离面板，不制造发光卡片效果；
- 宽度控制在约 `320–360px`，正文保持舒适行长；
- 档案卡位于节点上方，不压住轨道线，并根据节点所在的左、中、右区域调整锚点，避免越出视口。

卡片顶部显示日期与当天活动数量。随后按时间倒序列出当天全部活动。每条活动包含：

- 项目名；
- 活动类型的中文标签；
- 完整标题；
- 完整摘要；
- 存在 URL 时显示“查看 GitHub 记录 ↗”链接。

多条活动之间使用细分隔线，不嵌套第二层卡片。若 URL 为空，只隐藏链接，不隐藏活动内容。

## 交互与无障碍

- 桌面端：指针进入节点或详情卡时展开，离开整个节点区域后关闭。
- 键盘：每个节点都可聚焦；`focus-within` 展开详情卡，链接可继续按 Tab 访问。
- 触摸：点击节点切换展开状态；点击其他节点或轨道空白处关闭当前卡片。
- `Escape` 关闭当前详情卡并把焦点返回触发节点。
- 详情卡与触发节点建立明确的 `aria-controls`、`aria-expanded` 关系。
- 展开与关闭只使用轻微位移和透明度变化；`prefers-reduced-motion: reduce` 下取消位移动画。
- 移动端详情卡进入文档流，在对应日期节点下方展开，避免绝对定位造成横向溢出。

## 数据与边界

现有 `ActivityDay.items` 已包含项目、类型、标题、摘要和 URL，本次无需修改数据库或 API。组件必须容忍项目名或 URL 为空；日期内至少一条活动的约束继续由活动存储层保证。

卫星“定位最新活动”的交互继续保留。定位后应聚焦最新节点并展开详情，而不只是让圆点闪烁。

## 验证标准

自动化测试至少覆盖：

- 详情卡渲染当天全部活动，而非只渲染 `items[0]`；
- 每个节点均可聚焦，并包含展开状态所需的语义属性；
- 桌面轨道具有明确的底部安全距离，默认信息区位于轨道上方；
- 详情卡使用已确认的信号档案视觉标记；
- 移动端详情进入文档流；
- 减少动态效果偏好下不执行位移动画。

视觉回归至少检查 `2,048 × 928`、`1,440 × 900` 和 `390 × 844` 三种视口：轨道中段连续可见，详情卡不越界，全部文字可读，移动端无横向滚动。
