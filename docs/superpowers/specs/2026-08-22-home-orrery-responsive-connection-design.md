# 首页天体轨迹响应式连接设计

## 目标

修复首页月球、地球和黑洞在不同视口下与两条星尘轨迹错位的问题。桌面端现有构图、星球尺寸、交互与动画节奏保持不变；手机、平板、微信内置浏览器和 Safari 中，轨迹必须始终连接到天体的真实视觉边缘。

## 根因

当前手机端会重新定位和缩放三个天体，但粒子轨迹仍使用针对桌面母版写死的归一化坐标。底层固定轨迹图片又被拉伸至整个舞台，与动态 Canvas 使用不同几何来源，因此响应式布局后会发生双重错位。

## 设计

### 单一几何来源

移除固定轨迹图片在生产页面中的渲染。静态光带、明亮核心和动态粒子全部由同一个 Canvas、同一组贝塞尔曲线绘制，避免两层轨迹彼此偏移。

### 真实视觉锚点

在月球、地球和黑洞的现有链接中加入不可见、无交互的语义锚点：

- 月球锚点位于月球右侧边缘；
- 地球锚点位于地球左上侧边缘；
- 黑洞锚点位于暗核中心。

绘制器通过 `getBoundingClientRect()` 读取锚点与舞台的实际位置，将坐标换算为 Canvas CSS 像素。锚点跟随现有 CSS 布局，因此桌面、移动端和中间宽度不再维护独立轨迹端点。

### 曲线和视觉层

两条三次贝塞尔曲线均由实时端点和相对控制系数生成：

- 月球到地球使用浅弧线，线条较细、颜色从象牙白过渡到蓝白；
- 黑洞到地球使用更深的回旋弧线，线条较宽、颜色从金色过渡到蓝白；
- 控制点只依赖起点、终点和舞台比例，避免固定像素；
- 在同一路径上先画柔和外晕，再画低透明度细线，最后绘制运动粒子；
- Canvas 保持在天体下方，由天体遮挡末端，形成光带进入球体后方的空间感。

### 响应式和生命周期

首次布局完成后测量锚点。使用 `ResizeObserver` 监听舞台尺寸，并在 `resize`、字体完成加载和页面重新可见时更新几何。只在布局变化时重算路径，动画帧只采样已有曲线和绘制，避免持续触发布局读取。

Canvas 按 `devicePixelRatio` 设置后备分辨率，CSS 尺寸保持与舞台一致；DPR 上限为 2，以兼顾移动端清晰度和性能。

### 降级与无障碍

- 锚点测量失败或尺寸为零时不绘制错误轨迹，下一次有效布局再恢复；
- `prefers-reduced-motion: reduce` 下停止粒子运动，但保留同一曲线绘制的静态光带；
- 新增锚点为 `aria-hidden="true"`，不改变三个导航链接的语义和点击区域；
- 不增加依赖，不改变路由和页面数据。

## 验收标准

1. 1440、1280、1024、767、430、390、375 和 360 像素宽度下，两条轨迹均落在对应天体的视觉锚点，端点误差不超过 4 CSS 像素。
2. 桌面端三个天体的位置、尺寸、层级、悬停、键盘焦点和页面转场保持不变。
3. 手机端旋转屏幕、微信浏览器可视区域变化后，轨迹会重新对齐，无明显跳动。
4. 静态光带与动态粒子完全重合，不出现双轨、断口或穿过地球表面的现象。
5. 减少动态模式下没有持续粒子动画，但连接关系仍清楚。
6. 单元测试、首页契约测试、类型检查和生产构建全部通过。
7. 使用真实浏览器分别截图验收桌面端和移动端后，才允许发布到阿里云。
