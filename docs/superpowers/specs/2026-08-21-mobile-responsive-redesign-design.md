# Personal Blog 手机端响应式重构设计

**日期：** 2026-08-21  
**状态：** 已确认方向，待书面设计复核  
**范围：** 首页、Projects、Ideas 的手机端；共享导航仅限手机断点

## 目标

把当前“桌面布局压缩到窄屏”的三页手机体验，重构为内容完整、滚动自然、触控可靠的手机布局，同时保持桌面端现有视觉、动画、排版和交互不变。

本次成功不是简单消除横向溢出，而是让三个页面在手机上形成清楚的阅读顺序：

- 首页先建立身份与入口，再用完整但紧凑的宇宙场景收束体验；
- Projects 先浏览项目，再连续查看分页与近期活动；
- Ideas 让每条想法使用接近整屏的正文宽度，不再把桌面三列压进窄屏。

## 已观察到的问题

### 首页

- 简介、作品入口、联系方式和宇宙场景纵向割裂。
- 宇宙舞台在手机端仍使用放大的桌面构图，形成大面积空黑和星体裁切。
- 三个作品入口横向排列后文字与箭头拥挤，页面像被截取的桌面海报。

### Projects

- 项目列表继承桌面的高度限制和内部滚动，导致卡片被截断。
- 搜索、卡片、分页和活动时间线不是一条连续页面流。
- 地球背景占据过多纵向空间，并与项目文字竞争注意力。
- 活动时间线在手机上节点间距过大，信息密度过低。

### Ideas

- 日期、时间轴和正文仍是三列结构，正文宽度被严重压缩。
- 大字号、长行距与窄正文列叠加，造成单条内容异常高大。
- 搜索与日期筛选占据较多首屏空间，正文到达过晚。

### 共同根因

- 手机规则分散在共享样式和多个路由样式中，断点 `430/480/619/620/680/760/767px` 互相叠加。
- 固定视口高度、内部滚动容器、裁切和固定定位被组合使用。
- 当前规则主要改变尺寸，没有改变手机上的信息结构。

## 不可破坏的桌面端约束

1. `768px` 及以上不应用本次新增的手机布局规则。
2. 不改桌面端首页宇宙构图、动画轨迹、星体尺寸与位置。
3. 不改桌面端 Projects 的三列卡片、旋转地球、轨道曲线和交互。
4. 不改桌面端 Ideas 的时间轴、固定背景、搜索栏与奇点构图。
5. 不改数据库、API、页面内容、URL、SEO 元数据和发布流程。
6. Writing 页面正文布局不在本次范围内；共享导航的手机规则可以覆盖 Writing，但桌面规则不可变化。

实现时优先把所有新行为放入路由专属样式文件的 `@media (max-width: 767px)` 中。若必须调整共享导航，只能使用同一手机断点，并通过桌面视口回归验证证明无外溢影响。

## 设计方案

### 1. 共享手机页面框架

- 保留品牌标识与 Writing / Projects / Ideas 三个入口，使用紧凑的两层头部，不改桌面导航结构。
- 手机头部总高度控制在约 `88–96px`，支持安全区域，不遮挡正文。
- 所有主要链接、搜索框、筛选器和活动触发器至少提供 `44px` 的触控高度。
- 页面只允许浏览器主文档滚动；项目列表、时间线和正文列表不得再创建嵌套纵向滚动。
- `100svh/100dvh` 只用于背景或最低视觉高度，不得用于限制内容容器高度。

### 2. 首页手机布局

手机端改为单列正常文档流：

1. 身份简介；
2. 三个作品入口；
3. 联系方式；
4. 紧凑宇宙场景。

具体规则：

- 取消首页手机端的整页固定高度和内容裁切。
- 三个作品入口改为三行紧凑导航，每行包含图标、名称与箭头，避免横向挤压。
- 联系图标保持单行，但每个图标拥有独立的 `44px` 触控区域。
- 宇宙舞台高度控制在约 `420–480px`，月球、地球、黑洞和卫星必须全部处于可见构图内。
- 保留三个星体入口的语义链接和转场数据属性；手机端允许降低粒子密度或使用静态回退，但不删除导航能力。
- 不新增重量级图片，沿用现有手机资源与节流策略。

### 3. Projects 手机布局

手机端改为一条连续页面流：标题与搜索 → 项目卡片 → 分页 → 近期活动。

具体规则：

- 标题与搜索上下排列，搜索框占满内容宽度。
- `.project-card-grid` 在手机端设置 `max-height: none`、`overflow: visible`，彻底取消内部滚动。
- 项目卡片采用紧凑单列：仓库名与状态在上，摘要在中，语言和外链在下；卡片高度由内容决定。
- 地球缩小并限制在页面上半部作为低对比背景，不再贯穿整个项目列表。
- 分页紧接卡片列表，上一页、页码、下一页均保持可点击和不截断。
- 活动轨道在手机端继续使用纵向时间线，但减少节点间距，摘要始终可读；详情展开进入正常文档流。
- 卫星控制保留，点击后定位最近活动，且不会制造横向溢出或大段空白。

### 4. Ideas 手机布局

手机端取消桌面三列时间轴结构，每条记录改为单列内容块：

1. 日期与分类位于一行元信息；
2. 想法正文占满剩余内容宽度；
3. 时间轴退化为左侧轻量标记或条目分隔，不再占据独立列。

具体规则：

- 搜索与日期筛选保留在一行；当 `360px` 宽度不足时允许分成两行，不允许压缩正文。
- 正文使用约 `16px` 字号、`1.6–1.7` 行高，并保留 SQLite 中的主动换行。
- 日期、分类和装饰节点不得抢占正文主列。
- 奇点与地图保持背景角色，降低移动端对比度，不覆盖文字和控件。
- 列表使用主文档滚动；搜索栏若保持 sticky，必须在微信浏览器安全区域下方且不遮挡首条内容。

## 代码边界

优先修改：

- `src/styles/global.css`：仅共享手机导航和首页内容流中无法路由隔离的少量规则；
- `src/styles/home-orrery.css`：手机宇宙构图；
- `src/styles/projects-archive-v2.css`：手机项目流与活动时间线；
- `src/styles/ideas-journal.css`：手机 Ideas 单列结构；
- 现有展示契约测试：增加窄屏结构与桌面隔离断言。

只有在 CSS 无法表达语义顺序时，才最小修改 Astro 模板。不得复制一套独立手机页面，也不得引入运行时设备嗅探；响应式布局由 CSS 和现有语义 DOM 完成。

## 验证方案

### 自动验证

- 为三页增加手机规则契约测试，覆盖：正常文档滚动、无列表高度限制、Ideas 单列结构、首页有限舞台高度、最小触控尺寸。
- 增加桌面隔离契约：新规则必须位于 `max-width: 767px` 范围，桌面关键选择器和值保持不变。
- 运行内容测试、Astro 类型检查和生产构建。

### 视觉验收

手机视口：

- `360 × 800`：小型 Android；
- `390 × 844`：常见 iPhone；
- `430 × 932`：大屏手机。

桌面回归视口：

- `1440 × 900`；
- `2048 × 928`。

每个视口必须满足：

- `document.documentElement.scrollWidth === window.innerWidth`；
- 主要内容不截断、不被固定层遮挡；
- 手机端不存在嵌套纵向滚动；
- 主要触控目标不小于 `44px`；
- 桌面端与改动前的构图、信息密度和交互一致。

## 非目标

- 不重新设计桌面端。
- 不修改 Writing 正文和文章详情页。
- 不更换现有宇宙、地图、地球或奇点资产。
- 不新增内容、数据字段或后台能力。
- 不借本次工作重构无关的大型样式区域。
